## Як запустити зараз

```
cd src/backend && .venv/bin/uvicorn main:app --host 127.0.0.1 --port 8000
cd src/frontend && npx vite preview --port 5180 --strictPort --host 127.0.0.1
```

**Бекенд саме на `127.0.0.1`, і це змінилось.** Раніше тут стояло `0.0.0.0` з
поясненням, що QR паринга кличе телефон на LAN-адресу і без цього телефону не
було куди прийти. Пояснення було правдою рівно доти, доки не існувало окремих
дверей: тепер `security/tls_listener.py` тримає шифрований слухач на
`pair_tls_port` (типово 8443), і **саме він** — LAN-вхід для телефона. Відкритий
HTTP лишається на петлі.

Не повертайте `0.0.0.0`, щоб «полагодити паринг». Це виставляє на всю мережу
дані QR, сесійні токени й Сховище відкритим текстом поруч із шифрованим
слухачем, тобто мовчки знецінює його цілком. Якщо паринг не працює — дивіться,
чи піднявся TLS-слухач (`PHANTOM_SKIP_TLS=1` його вимикає), а не чи широко
слухає uvicorn.

Один процес тримає два порти: `:8000` — відкритий HTTP для робочого столу,
`:8443` — TLS для телефонів. Другий піднімає сам застосунок під час lifespan
(`security/tls_listener.py`), і саме він їде в QR разом із відбитком
сертифіката. `PAIR_TLS_PORT` мусить відрізнятися від `PORT`, інакше слухач
забере порт у власного uvicorn ще до того, як той спробує сісти.

`scripts/run-node.sh` робить те саме, але тримає HTTP лише на loopback:
у мережу тоді виходить сам лише шифрований :8443.

Вхід: `phantom` / PIN з `.phantom-data/identity/bootstrap_pin`. Якщо ядро
його не приймає — маркер застарів відносно бази; на цій інсталяції в рядку
досі лежить перший bootstrap-PIN, і взяти його можна лише з loopback.

Тільки `vite preview` — `npm run dev` білий, див. нижче. `vite preview`
проксює `/api` і `/ws` на `127.0.0.1:8000` так само, як dev-сервер: Vite 5
успадковує `server.proxy` у preview (`resolvePreviewOptions`). Тож екран
входу з написом «Ядро не відповідає» означає рівно одне — бекенда немає,
а не те, що preview чогось не вміє.

## Відкриті дефекти

**Нативна збірка падає.** `npx tauri build --no-bundle` →
`resource path binaries/phantom-backend-x86_64-unknown-linux-gnu doesn't exist`.
Tauri хоче вкласти бекенд усередину як sidecar. Або зібрати той бінарник
(PyInstaller з `src/backend`), або прибрати його з `resources` у
`tauri.conf.json` і лишити бекенд окремим процесом.

**Dev-режим білий.** `optimizeDeps.exclude` у `vite.config.ts` містить
`@ricky0123/vad-web`, а пакет — CommonJS без `module`/`exports`. Vite віддає
браузеру сирий CJS, і `import { MicVAD }` не зв'язується — React не монтується
взагалі. Продакшн-збірка ціла, бо Rollup із CJS справляється. Робітник дійшов
висновку: виключати треба лише `onnxruntime-web` заради його WASM-ресурсів,
а `vad-web` замело під ту саму гребінку помилково.

**Два макети без входу.** `app/App.tsx` більше не роутить самим лише URL:
`StateSurface` віддає «/» за `SystemState` — DIALOGUE, FOCUS, SENTINEL,
GHOST, DREAM, решта → SHADOW. Поза каркасом лишились `OperatorLayout`
і `PolisLayout`: їх не імпортує ніхто, `/operator` веде на
`AgentFoundryLayout`.

**Мертва смуга знизу.** Старі макети прибиті до `w-[1024px] h-[600px]`
(`OperatorLayout.tsx:132`, `DreamLayout.tsx:30`, `ProfileSelector.tsx:145,171`),
новий `DashboardLayout` — full-bleed. Разом дають порожнечу під згином.

**Англійські залишки.** Оболонка вже українська — док, вхід і «Огляд
системи» пройдені браузером. Лишилось точкове: роль оператора в картці
«Хто працює» приходить із бекенда як `Member`
(`api/routes_analytics.py:89`).

## Перевірка справжнім браузером

Playwright має chromium, але шлях за замовчуванням застарілий:

```js
chromium.launch({
  executablePath: '/home/kyrylo/.cache/ms-playwright/chromium-1228/chrome-linux64/chrome',
  args: ['--no-sandbox'],
})
```

Застосунок білішає на будь-якій непійманій помилці модуля, тож знімок екрана
сам по собі нічого не доводить — завжди збирай `pageerror` і HTTP ≥ 400.

`node` шукає `playwright` від теки самого скрипта, а не від робочої, тож
«запусти з `src/frontend`» рятує лише той скрипт, що там і лежить. Скрипт
із `/tmp` мусить імпортувати за повним шляхом
(`src/frontend/node_modules/playwright/index.mjs`).
