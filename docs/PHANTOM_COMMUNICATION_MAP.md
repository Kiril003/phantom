# Карта можливостей спілкування Phantom OS (Familiar Communication Map)

Цей документ описує концептуальну та технічну архітектуру **Драбини тактовності (Ladder of Tactfulness)** та супутніх механізмів, які перетворюють Phantom OS з настирливого голосового асистента на живого, контекстно-залежного фамільяра. 

Всі можливості спілкування розбито за кластерами з чітким відображенням на поточний програмний стек (FastAPI, SQLite, ChromaDB, Tauri, ESP32, React).

---

## 1. Драбина тактовності (Ladder of Tactfulness)

Комунікація Фантома підпорядкована засаді: **«найтихіший канал, який ще здатний виконати задачу»**. Мовчання або зміна модальності є повноцінним повідомленням.

```
       ТИХО
        │   ┌──────────────────────────────────────────────────────────────┐
        ├───► [1] HOLD: Притримати (Не кажемо зараз, збережено в сесії)    │
        │   └──────────────────────────────────────────────────────────────┘
        │   ┌──────────────────────────────────────────────────────────────┐
        ├───► [2] AMBIENT: Орб і світло (Колір, пульс дихання, earcon)       │
        │   └──────────────────────────────────────────────────────────────┘
        │   ┌──────────────────────────────────────────────────────────────┐
        ├───► [3] TEXT: Тихий текст (Рендеринг у чаті, гліф у периферії)   │
        │   └──────────────────────────────────────────────────────────────┘
        │   ┌──────────────────────────────────────────────────────────────┐
        ├───► [4] PING: М'який звук (Earcon-сигнал без слів)               │
        │   └──────────────────────────────────────────────────────────────┘
        │   ┌──────────────────────────────────────────────────────────────┐
        ├───► [5] VOICE: Голос (StyleTTS2 потік, DIALOGUE FSM)              │
        │   └──────────────────────────────────────────────────────────────┘
        │   ┌──────────────────────────────────────────────────────────────┐
        └───► [6] INTERRUPT: Перебивання (Barge-in, SENTINEL, критично)    │
            └──────────────────────────────────────────────────────────────┘
       ГУЧНО
```

### Технічне відображення рівнів:
*   **HOLD:** Подія паркується у `session_memory.py` у чергу відкладених думок (`deferred_thoughts: list[Thought]`). Вона чекає, поки `ContextEngine` зафіксує тривалий перехід користувача в стан спокою (відсутність інпуту, стабілізація HRV) або зміну стану `SystemState` на `OPERATOR` / `DIALOGUE`.
*   **AMBIENT:** Логіка бекенду надсилає WebSocket-івент через `websocket_hub.py` з оновленням сенсорних гормонів (`sentience`), що змінює колір та анімацію `FamiliarIK.tsx` на фронтенді, або транслює серійну команду на ESP32 для керування RGB LED стрічкою через `command_sender.py`.
*   **TEXT:** Повідомлення стрімиться дельтами через WebSocket з низьким когнітивним пріоритетом. На фронтенді `ChatWindow.tsx` не фокусує скрол на нових повідомленнях автоматично, якщо користувач знаходиться в стані `FOCUS`.
*   **PING:** Виклик earcon-файлу через локальну бібліотеку звуків. Бекенд надсилає івент `{"event": "earcon", "name": "ack_quiet"}`.
*   **VOICE:** Повноцінний запуск `voice_pipeline.py`. TTS-генератор стрімить аудіо-буфери безпосередньо у аудіо-вихід Radxa.
*   **INTERRUPT:** Аварійний перехід FSM у `SENTINEL` або активація VAD-інтеррапту в `stt_engine.py` (Barge-in), що миттєво глушить аудіо-вихід через `pyaudio` та надсилає контекст переривання до LLM.

## 2. Кластери комунікаційних можливостей

### Кластер А: Читання кімнати (Room Reading)
Аналіз фізичного та соціального простору навколо Radxa Dragon Q6A для автоматичного вибору «рунги» на Драбині тактовності.

*   **Діаризація сторонніх (Чужий голос):**
    *   *Механіка:* Модуль `stt_engine.py` (faster-whisper) розрізняє голоси (Speaker Diarization). Якщо виявлено голос, що не належить поточному `user_id`, бекенд тимчасово блокує вихід у канал `VOICE`, переводячи всі проактивні нуджі в тихий `TEXT` глоу на екрані.
*   **Нічний / Тихий режим (Темрява + Час):**
    *   *Механіка:* `sensor_parser.py` розбирає дані фоторезистора з ESP32. При Lux < 5 та локальному часі > 22:00, система автоматично переходить у стан `SHADOW` (тихе дихання орба, нуль голосу, знижена яскравість екрана).
*   **Зайнятість телефоном / Mute:**
    *   *Механіка:* Мобільний додаток-компаньйон надсилає через API стан дзвінка. Бекенд встановлює повний Mute та накопичує спостереження в чергу.
*   **Притримані думки (Conversational Gaps):**
    *   *Механіка:* Замість переривання, думка зберігається у `session_memory`. Коли користувач зупиняє набір тексту (понад 8 секунд) або виникає пауза у розмові (виявлена VAD), планувальник активує відкладену пропозицію з поміткою: `«Поки ти зупинився — є одна думка...»`.

### Кластер Б: Мовчання як вислів (Active Silence)
Мовчання не є пасивним очікуванням — це активна поведінка ШІ з периферійним відгуком.

*   **Реакція утримання («Я почув, але не лізу»):**
    *   *Механіка:* Коли вхідне повідомлення не потребує відповіді (наприклад, просте зауваження), ШІ повертає пустий текст, але встановлює емоційну реакцію. Фронтенд робить орб тьмянішим на 30% та запускає повільну хвилю дихання (breathe-pulse).
*   **Впевненість керує голосом (`[встановлено]` vs `[припускаю]`):**
    *   *Механіка:* У `prompt_builder.py` додано інструкцію:
        *   Факти зі статусом впевненості `confidence >= 0.85` (встановлено) ШІ має право озвучувати вголос.
        *   Гіпотези `confidence < 0.85` (припускаю) виводяться виключно текстом або карткою пропозиції на периферійній смузі, дозволяючи користувачу мовчки змахнути їх.

### Кластер В: Поліморфізм відображення (Generative UI)
ШІ вибирає найбільш відповідну форму представлення даних залежно від щільності уваги користувача.

```
                  ┌───────────────────────┐
                  │ Гліф (1 біт сяйва)    │ ── Периферійний погляд
                  └──────────┬────────────┘
                             │ (наближення погляду/dwell)
                             ▼
                  ┌───────────────────────┐
                  │ Інформаційний рядок   │ ── Швидке читання
                  └──────────┬────────────┘
                             │
                             ▼
                  ┌───────────────────────┐
                  │ Картка віджета        │ ── Базовий інпут
                  └──────────┬────────────┘
                             │ (клік / розгортання)
                             ▼
                  ┌───────────────────────┐
                  │ Інтерактивний канвас  │ ── Повна сесія FOCUS
                  └───────────────────────┘
```

*   **Динамічні форми рендерингу:**
    *   *Механіка:* `response_formatter.py` перетворює текстову відповідь на структурні Scene-компоненти:
        *   Числове значення ──► Рендеринг SVG-циферблата (`DialWidget.tsx`).
        *   Динаміка змін ──► Іскриста sparkline-лінія навколо сяйва орба (`SparklineWidget.tsx`).
        *   Керування порогом ──► Слайдер (повзунок) прямо всередині чат-бабла.
*   **Ambient-візуалізація даних:**
    *   *Механіка:* Замість спаму текстовими метриками ("CPU: 80%"), система малює дані на стані самого фамільяра:
        *   Колір орба (від теплого бурштину до холодного кобальту) відображає системний баланс гормонів (`sentience`).
        *   Темп пульсації орба відображає завантаження процесора.
        *   Повільний дрейф орба вгору/вниз показує довгостроковий тренд активності.

### Кластер Г: Розмовна текстура (Conversational Texture)
Механіки, що роблять мовлення Фантома наближеним до природного людського діалогу.

*   **Антиципаторне завершення (Anticipatory Completion):**
    *   *Механіка:* Коли користувач повільно вводить речення, бекенд на основі ToM та контексту прораховує найімовірніший кінець фрази. На фронтенді з'являється напівпрозорий сірий текст-підказка. Натискання `Tab` приймає завершення Фантома.
*   **Розмовна репарація (Self-Correction):**
    *   *Механіка:* Якщо LLM посеред генерації виявляє помилку (наприклад, потік повернув `[correction]`), вона не генерує повідомлення заново, а надсилає маркер заміщення. Фронтенд стирає останні слова в реальному часі та дописує новий скорегований варіант, імітуючи людське самовиправлення в розмові.
*   **Право не погодитись (Pushback):**
    *   *Механіка:* Якщо планувальник виявляє логічну помилку в діях користувача (наприклад, видалення критичного файлу), `RuntimeReferee` піднімає прапорець `objection`. Фантом прямо каже: `"Ні, я не буду цього робити, оскільки це призведе до X"`.

### Кластер Д: Тіло та мова без слів (Embodied Affect)
Фізичне представлення системи через механічні та світлозвукові канали.

*   **Орб як емоційний EKG:**
    *   *Механіка:* Анімаційний цикл орба постійно зчитує вектор sentience (`cortisol`, `dopamine`, `oxytocin`) зі `systemStore.ts` та змінює швидкість, хаотичність та амплітуду мікро-рухів IK-структури.
*   **Серво-кінематика камери:**
    *   *Механіка:* `face_tracker.py` через OpenCV обчислює координати обличчя користувача. На ESP32 надсилаються кути поворотів для сервоприводів. Коли Фантом активний (`DIALOGUE`), він тримає eye-contact; коли користувач зайнятий роботою (`FOCUS`), серво тихо відвертає камеру вбік, маркуючи повагу до приватного простору.
*   **Earcon-словник:**
    *   *Механіка:* Набір коротких звукових сигналів (100–300 мс) зшитий у `voice/earcons.py`:
        *   `success.wav` — дія завершена (короткий висхідний тон).
        *   `blocked.wav` — дія заблокована рефері (два глухих низьких тони).
        *   `thought_parked.wav` — думка відкладена в Hold (тихий шелест).

### Кластер Е: Пам'ять як розмова (Dialogue with ToM)
Користувач може напряму взаємодіяти з тим, що Фантом думає та знає про нього.

*   **Інтерактивна модель ToM:**
    *   *Механіка:* Запит `"Що ти про мене знаєш?"` активує генерацію наративного резюме ToM-моделі на основі таблиці `user_facts` та епох з `relationship_chronicle`.
*   **Корекція переконань у чаті:**
    *   *Механіка:* Користувач може прямо сказати: `"Це не так, забудь це"` або `"Я тепер не п'ю каву після 16:00"`. Це автоматично викликає чат-інструмент `delete_user_fact` або створює новий факт із пріоритетним таймстампом, витісняючи старі переконання.

### Кластер Є: Дикіші мегасистемні штрихи (Advanced Features)
*   **Мультикористувацька ToM & Egress-Guard:**
    *   *Механіка:* `db/models.py` підтримує декілька профілів користувачів. `pii_guard.py` перевіряє активний `user_id` сесії. Якщо один користувач запитує інформацію, засновану на ToM-моделі іншого користувача, Egress-Guard повністю вирізає ці дані з prompt/відповіді, повертаючи помилку доступу.
*   **Двоекранна безшовна тяглість:**
    *   *Механіка:* Tauri додаток на комп'ютері та мобільний компаньйон підтримують постійну синхронізацію через WebSocket-івент `session_handover`. Якщо користувач встає з-за столу, сесія розмови миттєво переноситься на екран телефону разом із поточним станом FSM та контекстом генерації.
