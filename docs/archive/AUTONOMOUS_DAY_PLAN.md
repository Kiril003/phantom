## North-star — what "professional SaaS product" means here

PHANTOM OS today is a single-tenant local AI assistant. Productisation =
turning it into a deployable service that another operator can stand up
and trust:

1. **Operability**: `/healthz`, `/readyz`, `/metrics` (Prometheus),
   structured JSON logs with `correlation_id`, OpenTelemetry tracing,
   error tracking surface.
2. **Security**: rate-limit per user, secrets out of repo, dependency
   audit pinned, security headers on all responses.
3. **Deploy**: multi-stage Dockerfile (ARM64 + x86_64), docker-compose,
   minimal `.github/workflows/ci.yml` running pytest + tsc + ruff.
4. **Doc surface**: OpenAPI spec is already auto-generated by FastAPI;
   we add a `README` deploy guide, `docs/OPERATIONS.md`, and a
   one-line "tenant onboarding" runbook.
5. **Cost accounting**: LLM token usage per user persists in
   `ai_tool_use_log` already; surface it via an admin endpoint.
6. **No dead code**: every committed file is on a hot path or has a
   live test exercising it. Anything orphaned gets deleted.

These six ship across phases 16 → 19 below.

## Daily cadence (cyclic — every 60–90 min)

```
1. read MEMORY.md → know current focus + open blockers
2. spawn 1–4 specialised agents in parallel (review / impl / test)
3. integrate their findings — code, tests, docs
4. run pytest + tsc → green gate
5. write MEMORY.md (update what changed, what's next)
6. git commit (atomic, prefixed: phase-XX or chore: ...)
7. self-critique: "what did I just skip? what's the weakest link?"
   → spawn devils-advocate critique agent if non-trivial
8. loop
```

**Compact survival**: every commit + every MEMORY.md write is a
checkpoint. Even if auto-compact strips conversation, the next iteration
re-reads MEMORY.md + last 5 commits and resumes without context loss.
