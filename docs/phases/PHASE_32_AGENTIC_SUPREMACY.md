# Phase 32: Agentic Supremacy (Еволюція Автономії)

Цей документ описує стратегічний план еволюції агента Phantom OS, мета якого — перевершити можливості сучасних CLI-асистентів (таких як **Claude Code** та **Gemini CLI**), та вивести взаємодію на новий рівень завдяки глибокій інтеграції з екосистемою Phantom OS (Голос, Зір, Desktop UI, Will Engine).

## 1. Аналіз конкурентів (Baseline)

Перед тим як робити "краще", необхідно досягти паритету з найкращими існуючими рішеннями.

### 1.1. Що ми беремо з Claude Code:
*   **Глибоке розуміння кодової бази (Repo-wide Context):** Здатність агента самостійно шукати інформацію по всьому репозиторію без потреби "згодовувати" йому файли вручну.
*   **Автономне редагування (File Editing):** Надійний інструментарій для редагування файлів (replace, write) з підтримкою множинних правок та гарантією цілісності коду.
*   **Delegation (Sub-agents):** Можливість розбивати складні задачі на паралельні потоки (дослідник, кодер, QA), делегуючи їх спеціалізованим субагентам.
*   **Unix-філософія:** Використання bash/shell як нативного інструменту для перевірки свого коду (linting, testing) перед завершенням задачі (Test-Driven Autonomy).
*   **Checkpoints:** Можливість зробити `git commit` або бекап перед ризикованими змінами, з функцією автоматичного відкату (Rollback) при невдачі.

### 1.2. Що ми беремо з Gemini CLI:
*   **Паралельне виконання (Parallel Tool Calls):** Здатність виконувати кілька пошуків (`grep_search`, `glob`) або читати кілька файлів одночасно для економії часу та токенів.
*   **Контекстна Ефективність:** Хитрі стратегії пошуку замість читання гігантських файлів повністю. Використання хірургічно точних regex.

## 2. Як Phantom OS перевершить цей Baseline (The "Next Level")

Claude Code та Gemini CLI обмежені терміналом. Вони — "сліпі та німі" текстові процесори. Phantom OS — це операційна система. Ми подолаємо обмеження CLI за допомогою таких технологій:

### 2.1. Мультимодальність як Стандарт (Зір + Голос)
*   **Не просто текст:** Замість того, щоб читати логи терміналу, Phantom може подивитися на екран (`SeeScreen`) або через камеру (`SeeCamera`), щоб перевірити, чи правильно зрендерився UI, чи з'явилася помилка в іншому вікні.
*   **Голосовий Зворотний Зв'язок:** Замість текстового спаму "Я знайшов 3 файли, зараз їх редагую", агент використовує `voice.say` для коротких, людських апдейтів ("Компіляція впала, шукаю помилку в роутері"), продовжуючи працювати у фоні.

### 2.2. Професійний UI (Desktop Shell & Artifacts)
*   **Відмова від "Чатового Спаму":** Terminal UI (як у Claude) змушує виводити все текстом. Phantom OS має GUI (React + Tauri).
*   **Artifact Widgets:** Коли агент аналізує процеси, базу даних або архітектуру, він не пише 10 абзаців тексту. Він повертає `DONE_SUBGOAL` зі структурованим Markdown або рендерить кастомний віджет (графік навантаження, таблицю процесів) прямо в чат-стрічці.
*   **Інтерактивність:** Користувач може клікнути на звіт агента, щоб розгорнути деталі, замість того, щоб скролити термінал.

### 2.3. Will Engine (Мотивація та Пріоритети)
*   CLI-тулзи чекають команди. Phantom OS діє проактивно.
*   **Resource-Aware Autonomy:** Якщо агент бачить, що тест впав, але у нього високий рівень `Security` (бажання стабільності), він може самостійно запустити фоновий процес виправлення багу, поки користувач займається іншими справами.
*   Агент адаптує свій рівень автономності залежно від рівня довіри (`trust_level`) та ризику задачі (`risk_level`).

## 3. План Реалізації (Execution Roadmap)

### Етап 1: Приборкання Базової Автономії (Fixing the Foundation) - **IN PROGRESS**
*   [x] Зменшення рівня `Curiosity` у Will Engine, щоб агент фокусувався на прямих рішеннях, а не на самонавчанні (`synthesize_capability`).
*   [x] Впровадження строгого формату звітів (Markdown, таблиці, Zero Fluff) у системний промпт тактичного планувальника.
*   [ ] Оновлення логіки обробки помилок `bash.run`: навчити агента аналізувати `stderr` і самостійно виправляти синтаксичні помилки без паніки.

### Етап 2: Покращення Інструментарію (CLI Parity)
*   [ ] Створити спеціалізовані інструменти `code_search` (на базі `grep_search` та `glob`) для швидкого сканування проекту, щоб агент не використовував `bash.run('grep ...')`.
*   [ ] Додати інструмент `git_workspace_manager` (вбудований у `ActionRegistry`), який дозволить агенту автоматично створювати гілки/worktree для експериментальних фіксів.
*   [ ] Налаштувати делегування (Subagents) через `AgentAssembleTeam` для складних архітектурних задач (напр., "напиши тест, поки інший агент пише код").

### Етап 3: Інтеграція Premium UI (The Supremacy Level)
*   [ ] Доробити компонент `ResponseRenderer`, щоб він розпізнавав специфічні теги агента (напр., `<system_report>`) і рендерив їх як скляні картки, а не текст.
*   [ ] Навчити агента комбінувати інструменти: зробити зміну в коді -> запустити збірку (`bash.run('npm run build')`) -> подивитися на результат (`SeeScreen`) -> відзвітувати голосом (`voice.say`).
*   [ ] Впровадити "тихий режим": коли агент довго працює (наприклад, сканує логи), він лише пульсує на UI і оновлює статус-бар, не спамлячи в чат, доки не знайде рішення.

## 4. Очікуваний Результат
PHANTOM OS більше не буде відчуватися як "ще один LLM у терміналі". Він стане цифровим співробітником (Digital Peer), який мовчки робить складну технічну роботу, візуалізує результати у красивому UI та комунікує голосом лише по суті.
