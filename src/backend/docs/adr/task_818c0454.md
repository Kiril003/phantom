## Rationale
Обраний підхід починається з глибокого розуміння обмежень цільової платформи Radxa Dragon Q6A, що є ключовим для уникнення попередніх невдач та оптимізації ресурсів. Розробка скрипта генерації ембеддінгів винесена в окрему під-ціль для паралельної розробки. Послідовне тестування (спочатку встановлення, потім бенчмаркінг) дозволяє ітеративно відсіювати несумісні рішення, мінімізуючи витрати часу та ресурсів. Фіналізація архітектури після аналізу гарантує, що вибір векторної БД буде обґрунтованим та інтегрованим у загальну систему довготривалої пам'яті.
